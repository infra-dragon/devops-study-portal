# Filesystem Structure

In Linux, everything is organized into a single tree that starts at one top point, `/`, called the **root**. There are no drive letters like `C:` — extra disks and devices are attached somewhere inside this one tree rather than kept separate.

## The nodes of the tree

**Each node of the tree is one of two things: a file or a directory (also called a folder).** A **file** holds data — text, image, etc. A **directory** holds other nodes: files and more directories.

Directories are what give the tree its shape. A directory can contain files and other directories, those can contain more, and so on. Files sit at the ends of the branches (they hold content but can't contain other nodes).

```
/                      (directory: the root)
└── home               (directory)
    └── alice          (directory)
        └── notes.txt  (file)
```

A name alone doesn't tell you which kind a node is — Linux treats an extension like `.txt` as just part of the name, not a marker of type, so a directory can be called `report.txt` and a file can have no extension at all. To find out for certain, use the **`file`** command, which prints the type of whatever you point it at:

```bash
$ file /home
/home: directory

$ file /home/alice/notes.txt
/home/alice/notes.txt: ASCII text
```

### Every directory has `.` and `..`

**Every directory automatically contains two special entries: `.` refers to the directory itself, and `..` refers to its parent — the directory one level up.** These aren't just things you type; they are real entries that exist inside every folder.

So from inside `/home/alice`, the `.` means `/home/alice` and the `..` means `/home`. 
At the very top (at `/`), the root's `..` simply points back to `/` itself, since there is nothing above the root.

## The Filesystem Hierarchy Standard (FHS)

**The FHS is an agreed-upon standard that says which directory holds which kind of file.** Because nearly every distribution follows it, you can sit down at any Linux machine and already know where the configuration, the logs, or the programs are — the layout is predictable instead of being different on every system.

For example, configuration is in `/etc` and logs are in `/var/log` on Ubuntu, on RHEL, and on Alpine alike.

## Key directories

**The root and the main branches:**

- **`/`** — the root of the whole tree; every other path lives underneath it.
- **`/etc`** — system-wide configuration files (plain text files that control the system and its services), such as `/etc/hosts`.
- **`/home`** — personal directories for regular users; your own files live in `/home/<username>`.
- **`/var`** — data that changes while the system runs, most importantly the logs in `/var/log`.
- **`/tmp`** — temporary files; usually cleared on reboot, so nothing important should live here.
- **`/opt`** — optional, self-contained third-party software that isn't part of the distribution's own packages.

**Where programs live:**

- **`/usr`** — the bulk of the installed system: most programs, libraries, and their shared data. Most of what you run day to day sits under `/usr/bin`.
- **`/bin`** — essential commands like `ls` and `cp`; on modern systems this is just a link into `/usr/bin`.
- **`/sbin`** — essential commands meant mainly for the administrator, like `ip` and `mkfs`.

**Virtual directories, generated by the kernel (not real files on disk):**

- **`/proc`** — live information about running processes and the kernel, presented as files.
- **`/sys`** — similar, exposing information about hardware and devices.

## The current directory

**At any moment your shell has a current directory — the folder you are "in" right now (also called the working directory).** When you log in or open a terminal, this starts as your home directory, `/home/<username>/`.

**Every command runs in the current directory unless you tell it otherwise.** If you give a command a relative path, or no path at all, it acts on things in the current directory; giving an absolute path (one starting with `/`) is how you point it somewhere else. Seeing and changing the current directory is covered in the navigation section.

## Absolute vs relative paths

**A path names a node's location by listing the directories you pass through, separated by `/`.** There are two ways to write one:

- **An absolute path starts from the root `/`** — it spells out the full route from the top, so it means the same thing no matter where you are.
- **A relative path starts from the directory you're currently in** — so its meaning depends on where you are. You walk it using node names to go down and `..` to go up.

The rule: a path that begins with `/` is absolute; anything else is relative.

```bash
/home/alice/notes.txt    # absolute: this exact file, starting from the root
notes.txt                # relative: the file in the current directory (same as ./notes.txt)
../bob/notes.txt         # relative: up one level, then down into bob's folder
```

When typing paths, `~` is shorthand for your own home directory, so `~/notes.txt` means `/home/alice/notes.txt`.
